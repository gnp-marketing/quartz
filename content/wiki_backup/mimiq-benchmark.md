# MIMIQ：文件中心式 GEO 評測基準

**Summary**: Multi-Intent MultI-Query 基準，以「文件」而非「查詢-文件對」為優化和評估單元，每個文件配 60 個涵蓋多種意圖和人物的查詢，支援訓練/測試分割，並能評估 HTML 結構。

**Sources**: Diagnosing and Repairing Citation Failures in Generative Engine Optimization.pdf（Tian et al., Virginia Tech + Zhejiang University, 2026-03-11）

**Last updated**: 2026-04-15

---

## 為什麼需要新的基準

### 現有基準的核心缺陷

現有 GEO 基準（GEO-Bench、E-commerce、Researchy-GEO）都採用**查詢中心式**設計：每個文件只配一個查詢，優化和評估都在同一個查詢上進行。

這個設計的問題：

**1. 混淆真正改善與過擬合**：一個優化若只針對一個特定查詢措辭，在表達相同意圖的其他措辭上可能完全失效。「提升了 30% 的可見度」可能只是過擬合那一個查詢的語言模式，並非真的讓頁面更可引用。

**2. 不符合內容創作者的真實處境**：創作者控制頁面內容，但**無法預測使用者的確切查詢措辭**。一個好的優化應該在任意措辭的相關查詢中都有效。

### MIMIQ 的設計哲學

把「文件」而非「查詢-文件對」作為優化和評估的基本單元。

## 基準規格

### 標準版（MIMIQ）

| 規格 | 數值 |
|---|---|
| 文件數 | 204 個 |
| 每個文件的查詢數 | 60 個 |
| 訓練查詢 / 測試查詢 | 20 / 40 |
| 總查詢數 | 12,240 個 |
| 來源 | ClueWeb22 索引（透過 GEO-Bench URLs + ChatNoir 搜尋補充）|
| HTML 評估 | ✅ 支援 |

**文件長度分布**：
- Short（< 2K 字元）：24 個
- Medium（2K–5K）：25 個
- Long（5K–10K）：84 個
- Very Long（> 10K）：71 個

**主題分布**：跨越 20+ 個主題，包含科技、健康、金融、教育、娛樂等，確保主題多樣性。

## 查詢生成流程

查詢生成透過三個維度的結構化框架模擬現實搜尋多樣性：

### 維度一：搜尋意圖（Intent）
基於 Broder（2002）和 Rose & Levinson（2004）的標準分類：
- **Informational**（資訊型）：使用者想了解某事
- **Commercial Investigation**（商業調查型）：使用者在比較選項
- **Transactional**（交易型）：使用者準備採取行動
- **Navigational**（導覽型）：使用者找特定頁面

對每個文件，過濾掉不合理的意圖（例如，純食譜頁面不會有導覽型查詢）。

### 維度二：使用者人物（Persona）
模擬不同類型的使用者（「領域專家」vs「隨意瀏覽者」、「高中生」vs「資深研究員」），每種人物使用不同的詞彙偏好和查詢風格。

### 維度三：措辭（Phrasing）
相同意圖和人物下，生成不同的語言表達方式，包括口語化、正式化、長尾短語等。

### 關鍵字提取策略

直接用整頁內容生成查詢往往引入雜訊（例如，一篇「公路旅行安全指南」頁面可能提取到「地圖」等不相關關鍵字）。MIMIQ 只從頁面**標題元資料**提取關鍵字，確保核心主題準確：

- **Core Keywords**：主要搜尋詞
- **LSI/Synonyms**：語義相關的同義詞和概念
- **Long-tail Phrases**：特定用戶需求的長尾查詢

### 品質控制

生成的查詢通過以下兩步清洗：
1. **去重**：移除語義等同的查詢（即使措辭不同）
2. **相關性過濾**：使用驗證模型確保每個查詢確實能由目標頁面回答，移除幻覺查詢

## 兩個挑戰性變體

### MIMIQ-OOD（Out-of-Distribution）

**目的**：評估優化是否能泛化到未見過的使用者行為模式。

**設計**：在同一批 50 個文件上，用**不同使用者人物**分割訓練和測試查詢——某些人物的查詢只出現在訓練集，另一些人物的查詢只出現在測試集。

**AgentGEO 在 MIMIQ-OOD 上的結果**：
- 引用率 70.62%（vs AutoGEO 的 64.18%，+6.44 個百分點）
- AgentGEO 優勢來源：保留原始頁面的資訊密度（AutoGEO 平均縮短頁面 43%，導致在 OOD 查詢上的資訊不足）

### MIMIQ-HTML（HTML 結構健壯性）

**目的**：評估系統在複雜或不規則 DOM 結構下的優化能力。

**設計**：從同一候選池中選取 50 個具有以下 HTML 解析問題的文件：
- Cookie 通知殘留
- 導覽欄殘留
- 頁尾元素
- JavaScript 代碼殘留
- 空頁面或 404 頁面
- 編碼問題
- 通用模板文字（「點擊此處」）
- 登入牆

**AgentGEO 在 MIMIQ-HTML 上的結果**：

| 方法 | 引用率（CR） | 忠誠度（TF-IDF） |
|---|---|---|
| Vanilla | 38.14% | — |
| AutoGEO | 45.96% | 65.77% |
| **AgentGEO** | **67.19%** | **82.20%** |

AgentGEO 在 HTML 結構問題頁面上的提升幅度最顯著（從 38% → 67%），驗證了 `noise_isolation` 和 `static_renderer_simulator` 工具對 HTML 解析問題的有效性。

## 對 GEO 研究的啟示

**1. 「文件中心」vs「查詢中心」的正確性問題**

真實世界的內容優化是「文件中心」的——你優化一個頁面，讓它在未知的查詢集合中更可引用。用「查詢中心」的評估方式測量這個目標，本質上是在評估過擬合能力，而非真正的優化效果。

**2. HTML 結構是被忽視的維度**

現有所有基準都只評估純文字內容，不評估 HTML 結構。但 AgentGEO 的結果顯示，HTML 解析問題造成的引用失敗佔 10.1%，且透過結構修復有顯著提升空間。未來基準需納入 HTML 維度。

**3. 訓練/測試分割的重要性**

CC-GSEO-Bench 雖然是文件中心式，但缺乏嚴格的訓練/測試分割，無法區分真正的泛化和查詢記憶。MIMIQ 的設計確保了嚴格的泛化評估。
