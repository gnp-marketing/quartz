# GEO 測量方法論：重複測量框架

**Summary**: GEO 能見度的正確測量方式——Jaccard 相似度、Rank Biased Overlap（RBO）兩種指標的定義與應用，以及從 Bootstrap 收斂分析推導出的最低執行次數和觀察窗口建議。

**Sources**:
- Don't Measure Once - Measuring Visibility in AI Search (GEO).pdf（Schulte, Bleeker, Kaufmann；聖加侖大學；arXiv:2604.07585v1；2026-04-10）

**Last updated**: 2026-04-16

---

## 為什麼需要新的測量方法論

傳統 SEO 測量的假設前提：**相同查詢 → 相同結果**。因此單次測量即可代表品牌的搜尋表現。

GEO 測量的根本挑戰：**相同查詢 → 每次結果都不同**。AI 搜尋引擎的輸出是機率抽樣，每次執行都是從輸出分佈中取一個樣本。單次樣本的統計誤差極大（SE = 0.370），幾乎沒有資訊量。

**Schulte et al. (2026) 的核心主張**：GEO 監測必須：
1. 多次重複執行同一個 prompt（每日至少 7–8 次）
2. 聚合多天的滾動視窗（建議 2–4 週）
3. 使用多樣化 prompt 組合（反映活動全貌）
4. 分引擎設定獨立基準

## 相似度指標一：Jaccard 相似度

### 定義

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

**直白解釋**：兩次查詢結果的集合重疊率。兩次都出現的項目 ÷ 至少出現過一次的項目。

- J = 0：兩次結果完全不同
- J = 1：兩次結果完全相同
- J = 0.35：約 35% 重疊，65% 不同

### 特性

| 特性 | 說明 |
|---|---|
| 集合運算 | 不考慮項目在清單中的順序 |
| 直觀易懂 | 直接解釋為「重疊比例」 |
| 適用場景 | 「是否被引用」比「排在第幾」更重要時 |
| 局限 | 無法區分排在第一 vs 排在最後的差異 |

### 邊界案例處理政策（Schulte et al.）

- **兩次結果都為空**：排除此對（標記 NaN）——兩次都沒有結果時，無法提供重疊資訊
- **一次有結果、一次為空**：J = 0.0（最大不一致）——一次有引用、一次完全沒有，視為最嚴重的不穩定
- **兩次都有結果**：正常計算 Jaccard

## 相似度指標二：Rank Biased Overlap (RBO)

### 為什麼需要 RBO

Jaccard 不分排序——排第一的來源和排第十的來源被同等對待。但在 AI 搜尋中，出現在回應開頭的引用能見度遠高於末尾。RBO 解決這個問題。

### 定義

$$\text{RBO}(S, T, p) = (1-p) \sum_{d=1}^{\infty} p^{d-1} \cdot A_d$$

其中：
- $S, T$：兩個排序清單
- $p$：持續性參數（0 < p < 1）。越高代表越重視尾端項目
- $A_d$：在深度 d 的重疊率 = $|S_{:d} \cap T_{:d}| / d$

**本研究使用**：$p = 0.9$，非外推最小值版本（截斷於 $k = \min(|S|, |T|)$）

$$\text{RBO}_{\min}(S, T, p) = (1-p) \sum_{d=1}^{k} p^{d-1} \cdot A_d$$

### RBO 的特性

| 特性 | 說明 |
|---|---|
| 排序敏感 | 前段重疊比後段重疊的貢獻大 |
| 保守估計 | 最小值版本是真實 RBO 的下界 |
| 比 Jaccard 更低 | 因為考慮了排序不一致的懲罰 |
| p=0.9 的含義 | 前 10 名的項目貢獻約 65% 的分數 |

### 實際觀測值

本研究中 RBO 系統性低於 Jaccard：
- 來源 RBO：0.21–0.26（vs Jaccard 0.34–0.42）
- 品牌 RBO：0.19–0.30（vs Jaccard 0.45–0.59）

**解讀**：不僅來源集合改變（Jaccard 已反映），連排序也大幅改變（RBO 的額外懲罰）。

## 最低執行次數：Bootstrap 收斂分析

### 方法

- 數據：128 個引擎–prompt 組合（4 引擎 × 8 prompts × 4 活動），各有 10 次執行
- 子抽樣：對每個 $n \in \{1,...,9\}$，無替換抽取 2,000 次子樣本
- 評估：SE = 2,000 個子樣本均值的標準差（越小越精確）
- 品牌分析：限於偵測率 ≥ 70% 的 3 個活動（共 1,216 個品牌序列）

### 結果：品牌偵測率

| 執行次數 (n) | SE | 95% CI (±) |
|---|---|---|
| 1 | 0.370 | 0.724 |
| 2 | 0.246 | 0.483 |
| 3 | 0.188 | 0.369 |
| 4 | 0.151 | 0.296 |
| 5 | 0.123 | 0.241 |
| 6 | 0.101 | 0.197 |
| **7** | **0.081** | **0.158** |
| **8** | **0.062** | **0.121** |
| 9 | 0.041 | 0.081 |

**閾值**：
- SE < 0.10 在 **n = 7** 達到（品牌偵測率監測的實務最低標準）
- SE < 0.08 在 **n = 8** 達到

### 單次執行有多不可靠？

SE = 0.370 代表：如果某品牌真正的偵測率是 50%，單次執行的結果可能落在 −22% 到 122%（名義上的 95% 區間，實際截斷到 [0,1]）。**一次查詢基本上沒有資訊量。**

### 結果：來源覆蓋 Jaccard SE

來源覆蓋的收斂比品牌偵測更慢（來源層級更隨機）：
- SE < 0.10 需要 **n = 8** 執行次數（SE = 0.096）

### 實務建議

| 監測目標 | 每日最低執行次數 | 原因 |
|---|---|---|
| 品牌能見度 | **7 次** | SE 降至 0.081，95% CI ±0.158 |
| 來源覆蓋 | **8 次** | SE 降至 0.096，95% CI ±0.187 |

## 時間觀察窗口：滾動視窗分析

### 方法

- 數據：1,726 個品牌序列（3 個活動 × 4 引擎 × 8 prompts × 多品牌）
- 每個序列包含 40–46 天的每日二元偵測記錄
- 計算：對各滾動視窗長度 $d$，計算所有可能的 $d$ 天窗口均值的 SE

### 結果

| 視窗長度 (d 天) | SE | 95% CI (±) |
|---|---|---|
| 1 | 0.322 | 0.631 |
| 2 | 0.238 | 0.467 |
| 3 | 0.201 | 0.393 |
| 5 | 0.160 | 0.313 |
| 7 | 0.135 | 0.264 |
| **10** | **0.107** | **0.210** |
| 14 | 0.080 | 0.157 |
| **21** | **0.053** | **0.105** |
| **28** | **0.033** | **0.065** |

### 閾值解讀

- **10 天**：SE < 0.10——可用於方向性監測（偵測大幅變化）
- **21–28 天（2–4 週）**：SE < 0.05——品牌比較的實務精確度
- **34 天**：SE < 0.02——高精確度分析

### 為什麼不用短窗口？

14 天視窗的 SE = 0.080（±0.157）——適合方向性判斷，但無法做細緻的品牌間比較。AI 搜尋引擎會定期進行演算法更新，短窗口可能把暫時性波動誤判為真實趨勢變化。

**2–4 週滾動窗口的雙重優點**：
1. 統計精確度足夠（SE < 0.05–0.08）
2. 自然平滑掉模型小更新引入的短期波動

## Prompt 設計原則

### 來自研究的觀察

同一個活動內，各 prompt 的 Jaccard 穩定性差異極大（從 < 0.2 到 > 0.8）。

| Prompt 類型 | 穩定性 | 原因 |
|---|---|---|
| 具體產品查詢（「哪雙跑鞋最好？」）| 較高 | 答案收斂在有限品牌集合 |
| 廣泛通用查詢（「跑步需要注意什麼？」）| 較低 | 答案可從大量不同角度切入 |

### 建議

- 使用 8+ 個多樣化 prompts 涵蓋一個主題活動
- 同時包含具體和通用查詢（反映真實使用者行為）
- 70% 的 AI 搜尋使用者問的是漏斗頂端問題（source: McKinsey, 2025），但這類查詢通常穩定性較低——需要更多次執行

## 方法論層級總覽

```
GEO 監測的三個維度
│
├── 每次測量：同一天同一 prompt 執行 7–8 次
│   └── 消除：模型隨機性雜訊
│
├── 跨日聚合：2–4 週滾動窗口
│   └── 消除：日間波動 + 小型演算法更新
│
└── 跨 Prompt 覆蓋：多樣化 prompt 組合
    └── 消除：Prompt 層級異質性偏差
```
