# 宏觀結構優化指南

**Summary**: 文檔層級的結構優化，包括標題層級、導航元素、段落流程和交叉參考設計，能貢獻 45% 的引用率改進。

**Sources**: Structural Feature Engineering for Generative Engine Optimization - How Content Structure Shapes Citation Behavior.pdf

**Last updated**: 2026-04-15

---

## 什麼是宏觀結構

宏觀結構是文檔的整體架構，定義了資訊如何從全局層面組織。包含：

- **標題層級（Heading Hierarchy）**：H1、H2、H3... 的嵌套結構
- **導航元素（Navigation Elements）**：內部鏈接、目錄
- **文檔流（Document Flow）**：各章節如何銜接和過渡

## 五大優化原則

### 原則 1：標題層級深度（Hierarchical Clarity）

**目標範圍**：標題深度 dh ∈ [3, 5]，各層級段落分佈 ≈ 0.3 ± 0.1

**為什麼**：
- 過深（dh > 5）：attention 在太多結構符號間分散，損傷注意力
- 過淺（dh < 3）：缺乏足夠的組織線索，檢索算法效果差

**實踐指南**：
```
H1 主題
  H2 主要概念 1
    H3 子概念 1.1
    H3 子概念 1.2
  H2 主要概念 2
    H3 子概念 2.1
```

### 原則 2：邏輯銜接（Logical Progression）

**目標**：相鄰章節間的語義相似度 > 0.7

**為什麼**：LLM 在解析段落轉換時的注意力模式顯示，邏輯連貫的流程能提升理解。

**實踐指南**：
- 每個章節開頭明確指出與前一章節的關係
- 使用過渡句連接概念
- 避免突兀的主題跳躍

### 原則 3：內部鏈接密度（Navigation Density）

**目標範圍**：Ld ∈ [0.15, 0.20]，平均路徑長度 ℓ_avg < 3

**為什麼**：生成式引擎需要進行多跳推理（multi-hop reasoning）。適當的內部鏈接支持這一過程。

**實踐指南**：
- 建立小世界網絡結構（small-world network）
- 關鍵概念對間的距離不超過 2 個鏈接
- 不過度互連（避免每個句子都是鏈接）

### 原則 4：段落均衡分佈（Section Distribution Balance）

**目標**：各層級的段落數量相對均勻

**為什麼**：不均勻的結構會導致某些部分在 attention 中被忽視。

**實踐指南**：
- 如果一個 H2 下有 10 個 H3，而其他 H2 只有 1 個，應考慮重新組織
- 使用相似性分數來判斷是否合併相關段落

### 原則 5：交叉參考富度（Cross-Reference Richness）

**目標**：支援迭代細化架構下的多輪搜尋

**為什麼**：某些生成式引擎（如 Perplexity AI、Phind）採用迭代檢索。豐富的交叉參考支持這一流程。

**實踐指南**：
- 在概念講解後提供「進一步閱讀」鏈接
- 建立概念之間的顯式關聯
- 使用相關概念提示

## 優化工作流

1. **提取當前結構**：分析現有標題層級和鏈接模式
2. **計算優化間隙**：評估與目標範圍的差距
3. **分層轉換**：
   - 如果標題過深，尋找語義相似的段落進行合併
   - 如果標題過淺，尋找高話題多樣性的段落進行拆分
4. **優化鏈接**：添加內部鏈接以達到目標密度（Ld ∈ [0.15, 0.20]）
5. **驗證語義完整性**：確保轉換後的文檔語義相似度 > 0.70
